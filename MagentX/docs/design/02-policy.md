# 网络策略（Policy）

## 页面定位

管理网络流量的路由规则。用户通过定义匹配条件和转发动作，控制哪些流量直连、哪些走代理、哪些走指定节点。

## 功能模块

### 1. 转发规则表

以 `Table` 组件展示所有规则，支持以下列：

| 列名 | 宽度 | 说明 |
|------|------|------|
| 规则名称 | ≥140pt | 规则的别名标识 |
| 匹配类型 | 140pt | 枚举值：`IP-CIDR`、`Domain Keyword`、`Domain Suffix`、`Match All` |
| 匹配内容 | ≥180pt | 等宽字体显示，如 `192.168.0.0/16`、`.cn`、`*` |
| 动作/目标节点 | 自适应 | 根据动作类型显示不同文案 |
| 操作 | 50pt | 删除按钮（垃圾桶图标） |

#### 匹配类型

| 类型 | 用途 | 示例 |
|------|------|------|
| IP-CIDR | 按 IP 段匹配 | `192.168.0.0/16`、`10.0.0.0/8` |
| Domain Keyword | 按域名关键词匹配 | `google`、`github` |
| Domain Suffix | 按域名后缀匹配 | `.cn`、`.local` |
| Match All | 匹配所有流量 | `*` |

#### 动作类型

| 动作 | 显示文案 | 含义 |
|------|----------|------|
| `DIRECT` | DIRECT (直连) 灰色 | 流量不经过代理，直接连接目标 |
| `PROXY` | PROXY (全局代理) 青色 | 流量经过当前选中节点的代理隧道 |
| `NODE` | 节点名称（青色）/ "指定节点"（灰色） | 流量经过规则绑定的特定节点 |

- 当 `PROXY` 动作绑定了 `targetNodeId` 时，显示该节点名称
- 当 `NODE` 动作绑定了 `targetNodeId` 时，显示该节点名称
- 未绑定节点时显示默认文案

#### 规则管理

- **新建规则**：点击右上角 `+ 新建规则` 按钮，添加一条默认规则（名称 "New Rule"，匹配类型 `Match All`，内容 `*`，动作 `PROXY`）
- **删除规则**：每行右侧垃圾桶按钮，删除对应规则

### 2. 连通性测试

| 控件 | 说明 |
|------|------|
| URL 输入框 | 输入测试目标 URL，默认 `http://www.gstatic.com/generate_204` |
| 测试按钮 | 发起经过代理隧道的 HTTP 请求 |
| 结果区域 | 显示响应首行（如 `HTTP/1.1 204 No Content`）或错误信息 |

**交互逻辑：**

1. 测试中显示加载指示器，按钮置灰
2. 代理未运行时按钮禁用
3. 成功时显示 HTTP 响应首行
4. 失败时显示错误描述

## 默认规则

首次启动时自动创建两条规则：

1. **LAN Bypass**：`IP-CIDR` / `192.168.0.0/16` → `DIRECT`（局域网流量绕过代理）
2. **Final Rule**：`Match All` / `*` → `PROXY`（其余流量走全局代理）

## 数据持久化

所有规则保存在 `AppState.policies` 中，通过 `UserDefaults` 以 JSON 格式持久化。
