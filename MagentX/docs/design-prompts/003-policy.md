# 003 Policy Page Design

## Context

Policy 页面用于管理网络转发规则，面向需要区分直连、代理和指定节点路由的用户。它不是代理启动页，而是规则检查与连通性验证页。

## Core Logic

页面先展示规则表，让用户按顺序查看每条规则的匹配类型、匹配内容和动作。新增规则生成一条默认规则，用户后续可编辑扩展。连通性测试使用当前选中节点和已运行的代理服务发起请求，只返回简短结果，帮助用户判断代理链路是否可用。

## Contract

- 输入：策略规则列表、节点列表、当前服务运行状态、测试 URL。
- 输出：新增规则、删除规则、执行连通性测试、展示测试结果。
- 规则字段：名称、匹配类型、匹配内容、动作、目标节点。
- 匹配类型：IP-CIDR、Domain Keyword、Domain Suffix、Match All。
- 动作类型：DIRECT、PROXY、NODE。
- 测试约定：只有代理服务运行时允许测试；结果只显示响应摘要或错误摘要。

## Corners

- 规则为空时，应保留新增规则入口。
- 匹配内容较长时使用等宽字体并允许截断。
- 目标节点不存在时，显示“指定节点”或降级提示，不崩溃。
- 测试 URL 为空或非法时，返回可读错误。
- 测试中按钮禁用，并显示 loading。
- 测试失败时只展示用户可理解的信息，不展示底层异常细节。
